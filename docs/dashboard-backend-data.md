# Dashboard Backend Data Contract

This document organizes the data the backend should expose for the read-only
bot dashboard. It is based on the current `HealthSnapshot`, SQLite state store,
paper runtime, and daily report code.

The dashboard must stay read-only. It can show status, reasons, positions,
watchlists, events, and raw JSON, but it must not expose order placement,
cancel, config mutation, or live-trading actions.

## Principles

- Expose recorded facts, not inferred trading advice.
- Keep every endpoint read-only: `GET` only.
- Return money, quantity, and indicator values as strings to preserve Decimal
  precision.
- Return timestamps as ISO-8601 strings. Existing runtime timestamps are UTC;
  UI can render them in `Asia/Seoul`.
- Do not expose secrets, access tokens, API keys, or raw environment values.
- Prefer stable dashboard-shaped payloads over making the frontend query SQLite
  tables directly.

## Current Read-Only Payloads

The existing `HealthServer` already supports these payloads:

### `GET /health` or `GET /status`

Top-level service health payload.

```json
{
  "status": "blocked",
  "mode": "paper",
  "timestamp": "2026-06-11T19:00:00+00:00",
  "ready": false,
  "watchlist": {
    "count": 0,
    "items": []
  },
  "positions": {
    "count": 0,
    "items": []
  },
  "open_orders": {
    "count": 0,
    "items": []
  },
  "blockers": [
    "runtime.symbols or runtime.universe_candidate_symbols is required"
  ]
}
```

Fields:

| Field | Type | Source | Meaning |
| --- | --- | --- | --- |
| `status` | string | `HealthSnapshot.as_payload()` | `ready` or `blocked`. |
| `mode` | string | runtime/config | Usually `paper`; may be `idle` for empty/default runtime. |
| `timestamp` | string | health snapshot | Payload generation time. |
| `ready` | boolean | runtime result | Whether the runtime can proceed without blockers. |
| `blockers` | string[] | runtime/config/reconcile | Human-readable reasons blocking operation. |
| `watchlist` | object | latest watchlist | Count and items for the selected watchlist. |
| `positions` | object | paper positions | Count and current paper positions. |
| `open_orders` | object | paper intents or broker orders | Count and open/read-only order-like items. |

### `GET /positions`

Current position list.

```json
{
  "count": 1,
  "positions": [
    {
      "symbol": "005930",
      "system": "S1",
      "status": "OPEN",
      "total_qty": "2",
      "avg_entry_price": "72000",
      "entry_n": "900",
      "current_stop_price": "70200",
      "last_unit_entry_price": "72000",
      "units": 1
    }
  ]
}
```

Current source fields come from `PositionState`:

| Field | Type | Meaning |
| --- | --- | --- |
| `symbol` | string | Stock symbol. |
| `system` | string | Turtle system, `S1` or `S2`. |
| `status` | string | `OPEN`, `CLOSING`, `CLOSED`, or `BLOCKED`. |
| `total_qty` | string | Total held paper quantity. |
| `avg_entry_price` | string | Average entry price. |
| `entry_n` | string | N value at entry. |
| `current_stop_price` | string | Current stop level. |
| `last_unit_entry_price` | string | Entry price of the latest unit. |
| `units` | number | Number of unit rows. |

Dashboard display:

- Show this in the positions table.
- If empty, show "no paper positions" rather than an error.
- Do not calculate live PnL unless the backend also supplies a current price
  snapshot.

### `GET /orders/open`

Open order-like list.

In paper mode, this may contain paper order intents generated by the latest
runtime pass:

```json
{
  "count": 1,
  "open_orders": [
    {
      "intent_id": "paper-...",
      "symbol": "005930",
      "side": "BUY",
      "signal_kind": "ENTRY",
      "system": "S1",
      "quantity": "1",
      "trigger_price": "72000",
      "observed_price": "72100",
      "fill_price": "72100",
      "entry_n": "900",
      "stop_price": "70300",
      "source_signal_id": "sig-...",
      "reason": "20-day breakout",
      "created_at": "2026-06-11T19:00:00+00:00",
      "mode": "paper"
    }
  ]
}
```

For broker reconcile data, the normalized open broker order shape is:

```json
{
  "order_id": "broker-order-id",
  "client_order_id": "client-order-id",
  "symbol": "005930",
  "side": "BUY",
  "status": "OPEN",
  "quantity": "1"
}
```

Dashboard display:

- Label paper intents clearly as simulated.
- Keep broker open orders separate from paper intents when both are available.
- Unknown or unresolved broker order statuses should appear as blockers.

### `GET /watchlist`

Latest operational watchlist.

```json
{
  "count": 1,
  "watchlist": [
    {
      "symbol": "005930",
      "current_price": "72000",
      "entry_high_20": "72500",
      "entry_high_55": "76000",
      "distance_to_20": "500",
      "distance_to_55": "4000",
      "nearest_distance": "500",
      "is_new": true
    }
  ]
}
```

Fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `symbol` | string | Stock symbol. |
| `current_price` | string | Latest completed-candle close used by watchlist. |
| `entry_high_20` | string/null | 20-day Donchian entry high. |
| `entry_high_55` | string/null | 55-day Donchian entry high. |
| `distance_to_20` | string/null | Absolute distance from current price to 20-day entry. |
| `distance_to_55` | string/null | Absolute distance from current price to 55-day entry. |
| `nearest_distance` | string | Smaller available distance. |
| `is_new` | boolean | Symbol was not in previous watchlist. |

Dashboard display:

- Sort order is already produced by the backend: nearest breakout first.
- Use skeleton/empty state when no watchlist exists yet.
- This is operational proximity data, not a buy signal.

## Additional Data Sections

### Runtime Events

Source: SQLite `runtime_events`.

Recommended endpoint: `GET /events?limit=100`.

Payload:

```json
{
  "count": 2,
  "items": [
    {
      "id": 12,
      "level": "WARN",
      "message": "paper_service_blocked",
      "payload": {
        "blockers": ["TOSS_CLIENT_ID is not configured"]
      },
      "created_at": "2026-06-11T19:00:00+00:00"
    }
  ]
}
```

Important event messages already used by the backend:

| Message | Meaning |
| --- | --- |
| `paper_service_started` | Paper service process started. |
| `paper_service_heartbeat` | One paper service loop completed. |
| `paper_service_blocked` | Service could not run because config/env was incomplete. |
| `market_session_state` | Market calendar result was recorded. |
| `paper_service_market_closed` | Market calendar blocked trading. |
| `premarket_watchlist_blocked` | Some watchlist candle fetches failed. |
| `premarket_watchlist_generated` | Watchlist was generated and saved. |
| `universe_generated` | Universe filtering completed. |
| `paper_reconcile_blocked` | Broker/local reconcile blocked runtime. |
| `paper_order_guard` | Order guard checks were evaluated. |
| `paper_order_intent` | A simulated paper order intent was recorded. |
| `paper_fill` | Simulated paper fill updated position state. |

Dashboard display:

- Use recent events for the activity/log panel.
- Use `level` for color/severity.
- Show `payload.blockers` prominently when present.

### Runtime Summary

Source: `summarize_runtime_events()`.

Recommended endpoint: `GET /events/summary?date=YYYY-MM-DD`.

Fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `total` | number | Number of events included. |
| `first_event_at` | string/null | Oldest event in the summary window. |
| `last_event_at` | string/null | Newest event in the summary window. |
| `by_level` | object | Counts by `INFO`, `WARN`, etc. |
| `by_message` | object | Counts by event message. |
| `blockers` | string[] | Unique blockers collected from payloads. |
| `paper_order_intents` | number | Count of paper order intents. |
| `paper_fills` | number | Count of simulated fills. |
| `paper_guard_checks` | number | Count of guard checks. |
| `paper_runtime_blocks` | number | Count of blocked/closed runtime events. |

Dashboard display:

- Use this for top cards and small counters.
- Keep the raw recent event list available below the summary.

### Operations Checks

Source: `check_operations_config()` and `operations_checks_payload()`.

Recommended endpoint: `GET /operations/checks`.

Payload:

```json
{
  "status": "blocked",
  "checks": [
    {
      "name": "config_exists",
      "passed": true,
      "message": "config exists: config/example.yaml"
    }
  ],
  "blockers": []
}
```

Dashboard display:

- Use this for a setup/readiness panel.
- Good checks can be collapsed; failed checks should be visible.

### Config Summary

Source: loaded `TradingConfig`.

Recommended endpoint: `GET /config/summary`.

Only expose safe, non-secret values:

```json
{
  "runtime": {
    "mode": "paper",
    "market": "KR",
    "timezone": "Asia/Seoul",
    "symbols_count": 3,
    "state_db": "state/turtle.sqlite3",
    "log_dir": "logs",
    "interval_seconds": 60,
    "watchlist_enabled": true,
    "watchlist_top_n": 20,
    "watchlist_name": "premarket",
    "universe_enabled": false
  },
  "strategy": {
    "n_method": "turtle",
    "stop_n": "2",
    "pyramid_step_n": "0.5",
    "max_units_per_symbol": 4,
    "max_total_long_units": 12
  },
  "toss": {
    "live_enabled": false,
    "base_url_configured": false,
    "account_seq_configured": false,
    "client_id_env": "TOSS_CLIENT_ID",
    "client_secret_env": "TOSS_CLIENT_SECRET"
  },
  "ai": {
    "enabled": false,
    "provider": "openai_compatible",
    "model": "bRadu/gemma-4-E2B-it-textonly",
    "base_url": "http://localhost:8000/v1"
  }
}
```

Do not expose:

- `TOSS_CLIENT_ID` value.
- `TOSS_CLIENT_SECRET` value.
- `TURTLE_AI_API_KEY` value.
- Any access token returned by Toss.

### Broker Snapshots

Source: SQLite `broker_snapshots`.

Current stored kinds:

- `holdings`
- `open_orders`

Recommended endpoint: `GET /broker/snapshots`.

Payload:

```json
{
  "holdings": {
    "captured_at": "2026-06-11T19:00:00+00:00",
    "payload": {}
  },
  "open_orders": {
    "captured_at": "2026-06-11T19:00:00+00:00",
    "payload": {}
  }
}
```

Current `latest_broker_snapshot(kind)` returns only payload. If the dashboard
needs "last synced at", add a store method that returns both `captured_at` and
`payload`.

### Market Data Snapshots

Source: SQLite `market_data_snapshots`.

Recommended endpoint: `GET /market-data/snapshots?symbol=005930&kind=candles`.

Use this for optional inspection panels, not for top-level dashboard cards.
Candles can be large, so keep a limit and prefer compact previews.

### Universe

Source: `universe_generated` runtime event payload.

Recommended endpoint: `GET /universe/latest`.

Payload shape from `Universe.as_payload()`:

```json
{
  "generated_at": "2026-06-11T19:00:00+00:00",
  "symbols": ["005930"],
  "count": 1,
  "decisions": [
    {
      "symbol": "005930",
      "included": true,
      "reasons": [],
      "completed_candles": 100,
      "average_daily_value": "1000000000",
      "last_close": "72000"
    }
  ],
  "policy": {
    "markets": ["KR"],
    "include_etfs": false,
    "min_price": "1000",
    "min_average_daily_value": "100000000",
    "average_daily_value_days": 20,
    "min_completed_candles": 56,
    "require_warnings_clear": true
  }
}
```

Dashboard display:

- Show included symbol count.
- Show excluded decisions only in a detailed drawer/table.

### Logs

Source: configured `log_dir`, usually:

- `logs/turtle-paper.out.log`
- `logs/turtle-paper.err.log`

Recommended endpoint: `GET /logs/tail?stream=stderr&lines=100`.

Payload:

```json
{
  "stream": "stderr",
  "path": "logs/turtle-paper.err.log",
  "lines": [
    {
      "line_no": 231,
      "text": "..."
    }
  ]
}
```

Rules:

- Read only from the configured log directory.
- Limit line count.
- If the log file is missing, return an empty list plus a clear message.

## UI Mapping

Recommended first-screen sections:

| UI Section | Backend Data |
| --- | --- |
| Top status badge | `/health.status`, `/health.ready`, `/health.mode` |
| Blocker banner | `/health.blockers`, event summary blockers |
| Summary cards | `/dashboard.status`, `/events/summary`, positions/watchlist counts |
| Watchlist table | `/watchlist` |
| Positions table | `/positions` |
| Open orders / paper intents | `/orders/open`, broker snapshots |
| Recent events | `/events?limit=50` |
| Setup checks | `/operations/checks` |
| Log tail | `/logs/tail` |
| Raw JSON button | `/dashboard` or `/health` raw response |

## Empty and Blocked States

The dashboard should treat these as normal states:

- Config missing or incomplete.
- Toss env vars missing.
- `runtime.symbols` and `runtime.universe_candidate_symbols` both empty.
- Market closed or holiday.
- Watchlist not generated yet.
- No positions.
- No open orders.
- Logs not created yet.

Blocked examples should render as warnings, not crashes.

## Implementation Order

1. Keep current read-only endpoints unchanged.
2. Add `GET /events?limit=100` from `SQLiteStateStore.list_runtime_events()`.
3. Add `GET /dashboard` as the frontend's single aggregate endpoint.
4. Add safe `GET /config/summary`.
5. Add `GET /operations/checks`.
6. Add log tail endpoint with path restrictions.
7. Add captured-at metadata methods for broker snapshots if needed.

## Data Not To Expose

- Toss client secret, access token, refresh token, or raw auth response.
- AI API key.
- Full process environment.
- Any endpoint that submits, cancels, or modifies orders.
- Any endpoint that toggles live trading.
- Any backend inference that presents itself as a trade recommendation.
